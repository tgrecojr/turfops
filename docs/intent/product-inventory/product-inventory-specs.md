# Product Inventory (the Shelf) — EARS Specs

Design: [product-inventory-design.md](product-inventory-design.md). Prefix `INV`. Facets: `SHELF` (the product record, vocabularies, category rules and scoping), `API` (product endpoints and their errors), `LLM` (assistant profile, precedence and refresh diff), `RATE` (the product label-rate rule), `LOG` (log suggestions and linking past applications), `NEED` (product needs and matching), `ENRICH` (inventory status and the feed's inventory pass), `SHOP` (shopping list), `UI` (Inventory page, stock pill, inventory badge, shopping panel).

A product's **facts** are its owner-owned, matchable fields (category, form, label rate, N-P-K, FRAC classes, herbicide timing, targets, amendment kind); its **profile** is the optional LLM description, informational only. A product **fits** a need when its facts meet every constrained axis of the need, whatever its stock; it **matches** when it fits and is **usable** (not archived, stock not Out). A **required** need is one not marked `optional`.

## The shelf

- [x] **INV-SHELF-001**: The system shall record each shelf product with a name, optional brand, a stock status of In stock, Low or Out, its facts, an optional LLM profile with the model and time that generated it, optional notes, an archived flag, and creation and update times; it shall record no quantity.
- [x] **INV-SHELF-002**: The system shall classify every shelf product in exactly one category: Fertilizer, Supplement, Fungicide, Herbicide, InsectControl, Seed, SoilAmendment, Surfactant or Other.
- [x] **INV-SHELF-003**: The system shall spell every product vocabulary value (category, form, stock status, herbicide timing, amendment kind, rate unit, target, profile descriptors) identically in the JSON API, the database and the LLM schema.
- [x] **INV-SHELF-004**: The system shall limit product targets to the closed list Grubs, SurfaceInsects, Ants, Termites, Ticks, Mosquitoes (pests); Broadleaf, Crabgrass, Nutsedge, Poa, Moss (weeds); Iron, Manganese, Magnesium, Zinc, Boron, Copper, Calcium (nutrients); Kbg, Ttf, Prg, FineFescue, Bermuda, Zoysia (species).
- [x] **INV-SHELF-005**: The system shall let a shelf product be logged under an application type only as follows (`ProductCategory::accepts`): Fertilizer and Supplement under Fertilizer or PlantFertilizer; Fungicide under Fungicide; Herbicide under PreEmergent or PostEmergent; InsectControl under GrubControl or Insecticide; Seed under Overseed; SoilAmendment under Lime or Sulfur; Surfactant under Wetting; an Other product under any type; any product under application type Other.
- [x] **INV-SHELF-006**: The web UI's list of shelf categories offered for an application type (`categoriesFor`) shall equal the categories `ProductCategory::accepts` allows for that type, always including Other.
- [x] **INV-SHELF-007**: Whenever the system saves a product's facts (add, edit) or derives suggested facts (profile refresh), it shall first scope them to the category: FRAC classes kept only on Fungicide or Other, herbicide timing only on Herbicide or Other, amendment kind only on SoilAmendment or Other, and targets only from the category's family (pests on InsectControl, weeds on Herbicide, nutrients on Fertilizer and Supplement, species on Seed, none on Fungicide, SoilAmendment or Surfactant, any on Other); N-P-K and the label rate are not scoped.
- [x] **INV-SHELF-008**: The system shall store a product's label rate only as an amount above 0 together with a unit of Lb, Oz or FlOz per 1,000 sq ft, or as neither.
- [x] **INV-SHELF-009**: When reading a stored product whose optional or list fact holds a value outside its vocabulary, the system shall drop that value with a logged warning and still return the product; an unknown stored stock status shall read as In stock.
- [x] **INV-SHELF-010**: When a shelf product is deleted, the system shall keep every application that referenced it, clearing the application's product link and keeping its recorded product name.
- [x] **INV-SHELF-011**: The products API shall serialize a product's facts as top-level fields of the product object, not nested.

## Product endpoints

- [x] **INV-API-001**: When `GET /api/v1/products` is called, the system shall return the lawn's products ordered by category then case-insensitive name, filtered to one category when `category` is given, and excluding archived products unless `include_archived=true`.
- [x] **INV-API-002**: When `GET /api/v1/products/:id` is called for an unknown id, the system shall return 404.
- [x] **INV-API-003**: When `POST /api/v1/products` is called with a name that is empty after trimming, the system shall return 400 and save nothing.
- [x] **INV-API-004**: When `POST /api/v1/products` saves a product without an assistant profile, the system shall set its facts to the owner's category, the owner's form (Other when not given), and the FRAC classes the curated product table (`frac_classes_for_product`, owned by Applications) resolves for the name.
- [x] **INV-API-005**: If `POST /api/v1/products` has no category, then the system shall save nothing and return 400 when the assistant was not requested, and 400 saying the assistant is not configured and a category is needed when the assistant was requested but OpenRouter is not configured.
- [x] **INV-API-006**: When `POST /api/v1/products` saves a product, the system shall use the owner's brand when given (otherwise the profile's manufacturer), default the stock status to In stock, and respond 201 with `{product, profile_error}`.
- [x] **INV-API-007**: When `PUT /api/v1/products/:id` is called, the system shall replace the product's name, brand, stock status, facts, notes and archived flag, never change its profile or provenance, store a blank brand or blank notes as absent, and return the saved product.
- [x] **INV-API-008**: If a `PUT /api/v1/products/:id` request has an empty name or gives only one of the label-rate amount and unit, then the system shall return 400 and change nothing.
- [x] **INV-API-009**: If `PUT /api/v1/products/:id` names an unknown id, then the system shall return 404.
- [x] **INV-API-010**: When `DELETE /api/v1/products/:id` is called, the system shall delete the product and return 204.
- [ ] **INV-API-011**: If a `PUT /api/v1/products/:id` request gives a label-rate amount of 0 or less, or an N, P or K percentage outside 0–100, then the system shall return 400 with a plain-language message naming the field and the allowed range, and change nothing.
- [ ] **INV-API-012**: When the product assistant fails while adding or refreshing a product, the system shall log the upstream detail and return to the owner only a plain-language message (in `profile_error` or the 503 body) saying the assistant could not identify the product and what to do next, never the provider's response body, the raw model output or an internal error string.
- [ ] **INV-API-013**: If `POST /api/v1/products` or `PUT /api/v1/products/:id` gives a name equal, case-insensitively after trimming, to the name of another of the lawn's products (archived included), then the system shall return 409 with a plain-language message saying a product with that name is already on the shelf, and save nothing.
- [ ] **INV-API-014**: If `DELETE /api/v1/products/:id` names an unknown id, then the system shall return 404 and delete nothing.

## Assistant profile

- [x] **INV-LLM-001**: When `POST /api/v1/products` is called with `assist` true or omitted while OpenRouter is configured, the system shall request a product profile for the lookup name (the brand followed by the name, unless the name already contains the brand case-insensitively), the lawn's grass type and USDA zone, and the owner's category as a hint.
- [x] **INV-LLM-002**: When the product assistant returns a profile on add, the system shall copy facts from it once: category, form, N-P-K, herbicide timing, targets, amendment kind, the suggested label rate as the stored label rate, and FRAC classes from the curated product table when it resolves the name, otherwise the profile's.
- [x] **INV-LLM-003**: When adding a product, the system shall let the owner's category and form, when given, overwrite the assistant's.
- [x] **INV-LLM-004**: If the product assistant fails while adding a product that has a category, then the system shall log a warning, save the product by hand, and report the failure in `profile_error`.
- [x] **INV-LLM-005**: The system shall request product profiles with a strict JSON schema in which every field is required (nullable ones may be null), enum values come from the app's vocabularies, FRAC values come from every FRAC class the app knows, and there is no application-interval or application-timing field.
- [x] **INV-LLM-006**: The product assistant's instructions shall tell the model to identify the exact retail product, lower its confidence when ambiguous, return Low confidence and Other or the owner's category for an unrecognized product without inventing a formulation, report only label facts, leave FRAC classes empty when unsure, suggest a label rate only when one is commonly published and it is confident, give no intervals or timing, list at most 4 cautions, and write a 1–2 sentence summary for the lawn's grass type and zone.
- [x] **INV-LLM-007**: The system shall read only a product's facts, never its profile, when matching products to needs or building the shopping list.
- [x] **INV-LLM-008**: When `POST /api/v1/products/:id/refresh-profile` is called, the system shall generate a new profile using the product's current category as the hint, store it with its model and time, leave the product's facts unchanged, and return `{product, suggested_facts, changed_fields}`, where `suggested_facts` are the facts the new profile implies (curated FRAC precedence applied, scoped to the suggested category) and `changed_fields` names each of category, form, label_rate, npk, frac_classes, herbicide_timing, targets and amendment_kind that differs from the current facts.
- [x] **INV-LLM-009**: If `POST /api/v1/products/:id/refresh-profile` is called while OpenRouter is not configured, then the system shall return 503 without calling the LLM; if the product id is unknown, it shall return 404.
- [ ] **INV-LLM-010**: If the product assistant's profile on add suggests a label-rate amount of 0 or less or an N, P or K percentage outside 0–100, then the system shall leave that one value out of the new product's facts (the label-rate amount and unit together; only the offending percentage of N-P-K), log a warning, and save the product with its other facts.
- [ ] **INV-LLM-011**: If the product assistant fails while adding a product that has no category, then the system shall log a warning, save the product by hand with category Other, the owner's form (Other when not given) and the curated FRAC classes for its name, and report the failure in `profile_error`.

## Label rate

- [x] **INV-RATE-001**: The system shall use a product's stored label rate only to pre-fill the rate on the application form and to show it on the product; no recommendation text, disease program, timing window or shopping-list item shall contain it.
- [x] **INV-RATE-002**: Where the Inventory page shows a product's label rate, it shall show it per 1,000 sq ft with the caveat "suggested by the assistant; verify against your label. Pre-fills the application form only." while it still equals the profile's suggested rate, and "from your label. Pre-fills the application form only." otherwise.

## Log and shelf

- [x] **INV-LOG-001**: When `GET /api/v1/inventory/suggestions` is called, the system shall return, grouped case-insensitively by name, every non-blank product name in this lawn's applications that have no product link and match no shelf product's name (case-insensitive, trimmed, archived products included), each with its most recent spelling, use count, last application date and distinct application types, ordered by use count then most recent use.
- [x] **INV-LOG-002**: When `POST /api/v1/products/:id/link-applications` is called, the system shall link the product to every unlinked application of this lawn whose product name equals the product's name (case-insensitive, trimmed), never reassign an application already linked, and return `{linked}` with the number of applications linked.
- [x] **INV-LOG-003**: While the log has suggestions, the Inventory page shall list them under "From your application log" with uses, last date and application types, each with "Add to shelf" (opening the add form pre-filled with the name and the first specific category its application types allow) and "Not now" (hiding it until the page reloads); it shall hide the list when it is empty or its fetch fails.
- [x] **INV-LOG-004**: When the owner clicks "Link past applications" on a product, the Inventory page shall report "Linked n past application(s) to <name>." or, when none matched, "No unlinked applications named "<name>" were found.", and refresh the log suggestions.

## Needs and matching

- [x] **INV-NEED-001**: The system shall let a recommendation source declare product needs, each with a plain-words label and any-of lists of categories, FRAC classes, targets and amendment kinds, an optional herbicide timing, and an `optional` flag for nice-to-haves.
- [x] **INV-NEED-002**: A product shall fit a need only when its category is among the need's categories (an empty list fits nothing) and it meets every constrained axis: shares a FRAC class when the need lists any, shares a target when the need lists any, has the need's herbicide timing or Both when the need gives one, and has an amendment kind among the need's when the need lists any.
- [x] **INV-NEED-003**: A product with no FRAC class, target, herbicide timing or amendment kind recorded shall not fit a need that constrains that axis.
- [x] **INV-NEED-004**: A product shall match a need only when it fits the need, is not archived and its stock is not Out; a Low product matches.
- [x] **INV-NEED-005**: Where a need requires nitrogen (the nitrogen-fertilizer need of a feeding), a product shall fit it only when the product's recorded N is above 0 or its N is unrecorded, so a recorded 0-0-x product never satisfies a feeding.
- [D] **INV-NEED-006**: Where a recommendation source declares a need as alternatives (each its own categories and constrained axes, such as the soil-test magnesium need: a Supplement with a Magnesium target, or a SoilAmendment of kind DolomiticLime), a product shall fit the need when it fits any one alternative.

## Inventory status and the feed's inventory pass

- [x] **INV-ENRICH-001**: When assessing a recommendation's needs against the shelf, the system shall list one match per (need, matching product) and the label of every required need nothing matches; optional needs shall add matches but never be counted or listed as missing.
- [ ] **INV-ENRICH-002**: When assessing a recommendation's needs, the system shall give no inventory status when there is no required need and no match, otherwise the first of: Need to buy (NotOnHand) when no required need is covered, Partly on hand (Partial) when only some are, Low when at least one product matches a required need and every product matching a required need is Low, and On hand (OnHand) otherwise; matches to optional needs shall not decide between Low and On hand.
- [x] **INV-ENRICH-003**: When the feed's inventory pass assesses a recommendation that declares needs and gets a status, it shall set the recommendation's inventory status and append one data point labelled "On hand" with value "<product> (<need>)" per match and one labelled "Not on shelf" with the need's label per missing need, all from source "Inventory".
- [x] **INV-ENRICH-004**: The feed's inventory pass shall never change a recommendation's id, severity or title, and shall leave recommendations without needs untouched.
- [ ] **INV-ENRICH-005**: If reading the lawn's products fails while the recommendation feed is built, then the system shall log a warning, skip the inventory pass, and return the feed with no inventory status and no inventory data points on any recommendation, rather than failing the feed.

## Shopping list

- [x] **INV-SHOP-001**: When `GET /api/v1/inventory/shopping-list` is called, the system shall build the list from the active recommendation feed (answered recommendations removed) and the lawn's non-archived products only, with no separate seasonal-plan lookahead, and return `{generated_at, items}`.
- [x] **INV-SHOP-002**: For each required need of an active recommendation, the shopping list shall add a Restock item, one per product, for every non-archived product with stock Low or Out that fits the need, whether or not another in-stock product also covers it.
- [x] **INV-SHOP-003**: For each required need of an active recommendation that is listed missing in its inventory status and that no Low or Out product fits, the shopping list shall add a Buy item, one per need label, labelled with the need's label and carrying its categories.
- [x] **INV-SHOP-004**: The shopping list shall never add an item for an optional need.
- [x] **INV-SHOP-005**: Each shopping-list item shall carry the distinct titles of the recommendations calling for it, in the feed's order, and an urgency equal to the highest severity among them.
- [x] **INV-SHOP-006**: The shopping list shall order items by urgency, most urgent first, then Buy before Restock, then by label.

## Inventory UI

- [x] **INV-UI-001**: The Inventory page shall load every product, archived included, group them by category in the order Fertilizer, Supplement, Fungicide, Herbicide, InsectControl, Seed, SoilAmendment, Surfactant, Other, sort each group by name case-insensitively, hide archived products behind a "Show n archived" toggle, and say "Nothing on the shelf yet. Click "+ Add Product" to get started." when the shelf is empty.
- [x] **INV-UI-002**: The Inventory page's add form shall take a required name, brand, category, form, stock status, notes and an "Identify with the assistant" checkbox (on by default); with the assistant on, the category may be left to the assistant; with it off, the form shall require a category before submitting.
- [x] **INV-UI-003**: While an add with the assistant is in progress, the Inventory page shall show "Identifying…" with a note that identification may take 10–30 seconds, and shall wait up to 60 seconds for the add or a profile refresh before timing out.
- [x] **INV-UI-004**: When an add returns a `profile_error`, the Inventory page shall say the product was saved by hand and that the owner can try "Generate profile" later.
- [x] **INV-UI-005**: Each product row on the Inventory page shall show the name, brand, a stock pill, form, N-P-K, FRAC codes, herbicide timing, amendment kind and targets, and the profile summary while collapsed; expanded, it shall show the details, a confidence warning when the profile's confidence is not High, a provenance line ("Profile generated <date> · <model>" or "Entered by hand — no assistant profile"), and Edit, Generate/Regenerate profile, Link past applications, Archive/Unarchive and Delete (after confirmation) actions.
- [x] **INV-UI-006**: When the owner clicks a product's stock pill, the Inventory page shall cycle its stock In stock → Low → Out → In stock and save it.
- [ ] **INV-UI-007**: The Inventory page's edit form shall offer category-specific facts: N-P-K for Fertilizer and Supplement, the FRAC picker for Fungicide, timing for Herbicide, amendment kind for SoilAmendment, and target checkboxes for exactly the targets the system keeps on save for the category (INV-SHELF-007): pests on InsectControl, weeds on Herbicide, all seven nutrients on Fertilizer and Supplement, species on Seed, none on Fungicide, SoilAmendment or Surfactant, and every target on Other.
- [x] **INV-UI-008**: When a profile refresh returns changed fields, the Inventory page shall show "The refreshed profile suggests changes to <fields>" with "Review in editor" (opening the edit form pre-filled with the suggested facts) and "Ignore", and shall not change the product's facts until the owner saves.
- [x] **INV-UI-009**: Wherever a recommendation carries an inventory status (dashboard alert cards, Recommendations list and detail pane), the web UI shall show one inventory badge with symbol, label and status color: ✓ On hand (green), △ On hand, running low (amber), ✕ Need to buy (red), ◐ Partly on hand (amber), with a tooltip listing each need's product (and its stock when not In stock) or "not on shelf".
- [x] **INV-UI-010**: The web UI shall show a stock status only as symbol and label over its status color: ✓ In stock (green), △ Running low (amber), ✕ Out (red).
- [ ] **INV-UI-011**: The Inventory page shall show the full shopping list above the product list, every item with its kind (Buy or Restock), label, stock when not In stock, categories, the recommendations it is for, and its urgency as the severity's symbol and label together in ink text on a tint of its status color (FEED-REC-004); it shall say "Nothing to buy — the shelf covers every active recommendation." when empty, and re-fetch whenever any product's stock, archived flag or update time changes.
- [x] **INV-UI-012**: The dashboard shall show a compact shopping list of the first 4 items with "n more" and "View all" links to `/inventory`, and shall hide it while loading, when empty, or when its fetch fails.
- [ ] **INV-UI-013**: If a request from the Inventory page (product list, add, edit, stock pill, archive, delete, refresh, link) or the shopping list fails, then the page shall show the server's plain-language `error` message, point to Settings when no lawn profile exists, name the unavailable source on 503, and ask the owner to try again on a timeout, never showing a status code, a JSON body or upstream detail.
